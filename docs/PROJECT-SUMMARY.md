# 에릭네 청소가게 (CleanMate) - 프로젝트 진행상황 요약

작성일: 2026-08-29 (Cowork 세션)

## 이번 라운드에서 반영 (폰트 교체 + 엑셀 내보내기 + 웹 배포)

### 1. 폰트 교체
- **한글: 마루부리(MaruBuri)** 로 변경. 네이버가 배포하는 서체로 상업적 사용까지 무료라, 오빠 가게 앱에 그대로 써도 문제 없어요. Regular/Bold 두 굵기 적용.
- **영문/숫자: Playfair Display** 적용.
  - podo님이 주신 Albra Serif는 **TRIAL(체험판)** 이었어요. 동봉된 라이선스 원문에 "상업·개인 프로젝트 사용 금지 / 서버에 설치 금지 / 정식 구매 전 공개 배포 금지"가 명시돼 있어서, 실제 가게 앱에 넣고 웹에 올리면 라이선스 위반이 돼요.
  - 그래서 분위기가 가장 가까우면서 상업적 사용이 자유로운(SIL Open Font License) Playfair Display로 대체했어요. 나중에 Albra 정식 구매하시면 폰트 파일만 교체하면 되게 구조를 잡아뒀어요 (style.css의 `AppSerifLatin` 부분만 교체).
- 영문은 Playfair가, 한글은 마루부리가 그리도록 `unicode-range`로 분리해서 한 스택으로 묶었어요.
- 폰트 파일을 전부 **woff2로 변환**해서 용량을 크게 줄였어요 (그리운 프롬솔 1301KB → 683KB 등). 폰트 폴더 전체가 1.5MB로, 폰트를 2종 추가했는데도 예전보다 가벼워졌어요.
- 설정 화면 폰트 선택은 그대로 유지 (마루부리(기본) / 그리운 프롬솔 / HS 활공명조).

### 2. 관리자 엑셀 내보내기 (신규)
- 관리자 화면 우측 상단에 **"⬇ 엑셀"** 버튼 추가: 크루현황 / 승인대기(근태요청) / 가입승인 / 체크리스트 관리 / 활동로그
- 관리자 메뉴에 **"전체 자료 엑셀로 내보내기"** 추가 — 위 5가지를 시트별로 나눈 엑셀 파일 하나로 저장 (매니저 이상만 가능)
- 진짜 `.xlsx` 파일로 저장되고, 열 너비도 내용에 맞춰 자동 조정돼요. 파일명에 날짜가 붙어요 (예: `크루현황_20260829.xlsx`)
- 인터넷이 끊겨 엑셀 라이브러리를 못 불러오면 자동으로 CSV로 저장 (CSV도 엑셀에서 바로 열리고, 한글이 안 깨지도록 BOM 처리)
- 크루현황 시트에는 입사일로부터 자동 계산된 **Induction 만료일 / 남은 일수 / 상태(정상·30일이내·7일이내·만료됨)** 가 함께 들어가서, 엑셀에서 바로 정렬·필터해서 관리할 수 있어요

### 3. 웹 배포
- 앱을 실제 웹 주소로 배포해서, 파일 다운로드 없이 폰에서 링크만 열면 바로 쓸 수 있게 했어요.

## 이전 라운드 반영 (로그인 오류 수정 + 백엔드 3단계 + 코드 정리)
- 관리자/크루 로그인이 "0000"으로 안 되는 문제 확인 및 대응: 로그인 화면에 "기본값(0000)으로 초기화" 링크 추가 (예전 테스트 중 저장된 비밀번호/PIN이 남아있어 새 기본값이 안 먹히는 경우를 위한 안전장치)
- 죽은 코드 정리: 안 쓰이는 옛날 `decideJoin()` 함수(실제로는 `decideJoinReal()`이 쓰이고 있었음, 중복 정의되어 있던 것) 삭제
- 백엔드 연동 3단계: "가입 신청(Join)" 접수 + 관리자 승인/거절도 이제 Supabase에 저장되어 여러 관리자/기기에서 같은 신청 목록을 보고 처리 가능. 실행할 SQL: `supabase-phase3-join.sql`

## 백엔드 연동 2단계 (체크리스트 항목 공유)
- 관리자가 사이트/요일별로 등록하는 체크리스트 "항목 목록"이 이제 Supabase에도 저장되어, 다른 관리자가 다른 기기에서 등록/삭제해도 서로 반영됨. 크루가 체크리스트를 열 때도 서버 최신 목록을 불러와 보여줌.
- (직원별 "체크 완료" 표시 자체는 아직 로컬 저장만 — 실제 로그인 인증이 붙어야 "누가 체크했는지" 정확히 서버에 기록할 수 있어서, 이 부분은 다음 단계로 미뤘어요.)
- 실행할 SQL: `supabase-phase2-checklist.sql` (SQL Editor에서 실행 필요)

## 백엔드(Supabase) 연동 1단계
- Supabase 프로젝트(`hhjxbqcpzccadtptbdqf`)를 실제로 연결 시작. 지금은 아래 2가지 기능만 "여러 기기에서 공유"되도록 전환:
  - **활동 로그 (activity_log)**: 관리자 메뉴의 "활동 로그"에 기록되는 모든 항목이 이제 로컬 저장 + Supabase 서버 저장을 동시에 함. 서버에서 최신 기록을 불러와 화면에 다시 그려줘서, 다른 관리자가 다른 기기/브라우저에서 봐도 같은 로그가 보임.
  - **근태 요청 (requests: 휴가·오버타임·대체근무)**: 신청 시 로컬 저장 + Supabase 서버 저장 동시 진행. 관리자 승인화면도 서버에서 최신 목록을 불러와 병합 표시. 승인/거절 처리 시 서버의 해당 요청 행도 함께 업데이트(상태값 + 처리자).
- 두 기능 모두 "로컬 우선 저장 → 화면에 즉시 반영 → 백그라운드로 서버에도 저장/조회" 방식이라, 인터넷이 잠깐 끊기거나 서버 설정이 아직 안 되어 있어도 앱 자체는 멈추지 않고 로컬 저장만으로 계속 동작함 (안전장치).
- Supabase 대시보드에서 실행해야 하는 SQL을 `supabase-phase1-run-this.sql` 파일로 별도 전달함 — **아직 실행 확인이 안 됐다면 SQL Editor에서 꼭 한 번 실행해줘야 실제로 여러 기기 공유가 작동함.** 실행 전까지는 지금처럼 기기별로만 저장됨(에러는 안 남, 콘솔에 경고만 뜸).
- 보안 상태: 지금은 실제 로그인 인증이 없어서, Supabase의 Row Level Security를 "공개 키로 누구나 읽고 쓸 수 있음"으로 열어둔 임시 상태. 내부 소규모 사용 기준으로는 괜찮지만, 실제 로그인 인증이 붙기 전까지는 임시 조치로 표시해둠.

## 코드 검증 습관 (중요)
코드 수정할 때마다 아래 3가지 자동 검증 필수:
1. `node --check app.js` (문법 오류 확인)
2. HTML의 모든 `onclick="함수명(...)"` 이 app.js에 실제로 정의되어 있는지 대조
3. app.js의 모든 `getElementById("id")` 가 index.html에 실제 존재하는 id인지 대조
4. app.js의 `views` 배열 각 항목에 대응하는 `id="view-*"` 엘리먼트가 index.html에 있는지 대조
